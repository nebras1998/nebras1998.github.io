# تحليل قسم الفني - تطبيق الفنيين (Technician Section)

> تقرير قراءة فقط — مبني على فحص الكود الفعلي، جميع المراجع تشير إلى ملف:سطر حقيقي.
> جميع الملفات المطلوبة موجودة في الكود (لا توجد ملفات ناقصة في المسارات المذكورة).

## 1. نظرة عامة على القسم

القسم هو تطبيق جوال (أساسًا) مخصص للفني الميداني، مبني كمسار `src/app/technician/*` داخل نفس تطبيق الإدارة. يغطي فعليًا خمس وظائف: تسجيل الحضور/الانصراف اليومي، عرض المهام المسندة (الفحوصات غير المكتملة) وإدخال نتائجها، إدارة رحلات المركبات، مسح QRs للوصول السريع لتفاصيل عينة، وعرض ملف شخصي للقراءة فقط. الدخول عبر صفحة `login` خاصة تسجّل عبر `loginTechnician` في `src/store/useAuthStore.ts:140`. الحماية على مستوى `proxy.ts` تسمح بدورَي "فني" و"مدير" (`src/proxy.ts:10`). كل الصفحات مكوّنات عميلية (`'use client'`) تتصل مباشرة بـ Appwrite SDK من المتصفح — لا توجد Server Components أو Server Actions في هذا القسم إطلاقًا.

## 3. تحليل تجربة الاستخدام (UX) للفني الميداني تحديدًا

### أحجام اللمس والأزرار
- **جيد**: الأزرار الرئيسية وواسعة `py-3` مع `text-lg` (`SubmitButton.tsx:27`, أزرار تسجيل الحضور `attendance/page.tsx:93` `py-3 text-base`, زر "بدء رحلة جديدة" `vehicles/page.tsx:82` `p-5`, زر حفظ النتيجة `tests/[id]/page.tsx:350` `text-lg`). ارتفاعها فعال ~48px.
- **جيد**: الشريط السفلي بخمسة عناصر `min-w-[60px]` بارتفاع ~44px (`TechnicianBottomNav.tsx:26`)، حقل الإدخال `p-3 text-base` (16px) يمنع تكبير iOS التلقائي (`TextField.tsx:6`).
- **ضعيف**: زر حذف مكعب داخل نتائج الفحص هو أيقونة `X` بحجم 16 بلا padding (`TestResultRowsEditor.tsx:71`) — هدف لمس ≤16px. زر "إضافة مكعب" `text-sm` مع أيقونة 14 (`TestResultRowsEditor.tsx:76-77`). زر خروج الداشبورد `px-3 py-1.5 text-sm` (≈30px) (`dashboard/page.tsx:63`). زر تحميل QR `px-5 py-2` (≈36px) (`samples/[id]/page.tsx:175`). كلها دون الحد الموصى به (44×44px) ليد متسخة/إضاءة شمس.

### التعامل مع انقطاع/ضعف الاتصال
- **لا يوجد أي تعامل**: لا Service Worker، لا `navigator.onLine`، لا قائمة انتظار كتابة، لا IndexedDB (فشل البحث في `src` أسفر عن صفر نتائج). `public/manifest.json:8` يحوي `"icons": []` وبدون `sw.js` — التطبيق غير قابلاً للتثبيت فعليًا أو التشغيل دون اتصال رغم `display: standalone`.
- جميع عمليات الكتابة استدعاءات SDK مباشرة؛ عند الفشل toast فقط.
- **خلل خطر**: في `attendance/page.tsx:43` فحص "سجل اليوم" له `catch {}` صامت. على شبكة ضعيفة إذا فشل جلب السجل يبقى `existingRecordId=null` فيُنشأ سجل **ثانٍ** لنفس اليوم عند الحفظ (تكرار/تداخل).
- **مضلل**: الداشبورد يجلب المهام بدون `catch` (`dashboard/page.tsx:28-33, 39-46`). عند فشل الشبكة يُعرض `EmptyData "لا توجد مهام حالياً"` — يبدو للفني كأنه بلا عمل معين بدل رسالة خطأ/إعادة محاولة.

### الماسح (`scanner/page.tsx`)
- على فشل تشغيل الكاميرا (رفض الصلاحية): رسالة `"فشل تشغيل الكاميرا. تأكد من السماح بالوصول."` + زر "إعادة المحاولة" يعيد تهيئة الماسح (`scanner/page.tsx:53-57, 91-98`). مقبول.
- على باركود غير صالح: رسالة + إعادة تشغيل تلقائية عبر `scanKey` (`scanner/page.tsx:47-49`). مقبول.
- **لا تعامل للإضاءة المنخفضة**: لا كشاف (torch)، لا تبديل كاميرا أمامية/خلفية — يستخدم فقط `facingMode:'environment'` (`scanner/page.tsx:31`).
- نجاح المسح يعمل `window.location.href` (إعادة تحميل كاملة) (`scanner/page.tsx:45`) بدل تنقل خفيف.
- **عدم توافق**: QR المولّد في صفحة العينة يشير إلى `/dashboard/samples/{id}` (`samples/[id]/page.tsx:129`). داخل التطبيق يعيد الماسح كتابته إلى `/technician/samples/{id}`، لكن لو مسح الفني الباركود بقارئ خارجي سيُفتح رابط Admin يعترضه `proxy` (`proxy.ts:92-94`) إلى `/unauthorized`.

### تدفق تسجيل نتيجة فحص
- نموذج صفحة واحدة (نتيجة + وحدة + تاريخ + مكعبات + ملاحظات + زر حفظ) — **لا تنقلات متعددة**، وهذا جيد.
- لكن: الحفظ يحوّل الحالة إلى `'مكتمل'` مباشرة (`tests/[id]/page.tsx:156`) بلا حالة وسيطة "تحت الفحص"، وبعدها **تختفي** الفحوصات المكتملة من شاشة الفني (`dashboard/page.tsx:30` يشترط `notEqual('status','مكتمل')`). النتيجة: في فحص مقاومة الضغط (عمرين 7 و28 يومًا — نوع `dual_age`) يعبّئ الفني عمر 7 أيام فقط ويحفظ فيتعين "مكتمل"، ثم **لا يستطيع الرجوع** لإضافة نتيجة 28 يوم لاحقًا.
- لا يوجد مؤشر تقدم بصري دائم للحفظ سوى indie spinner في زر الإرسال + `toast.success` ثم `router.push` فوري إلى الداشبورد (`tests/[id]/page.tsx:253-254`) — في موقع مشتّت قد يفوت الفني تأكيد النجاح. لا يوجد تأكيد مراجعة/ملخص قبل الإقفال النهائي.

## 4. الفجوات الوظيفية المحتملة (مقارنة بقسم الإدارة)

ملاحظة: قسم الإدارة (`src/app/dashboard/*`) يملك وحدات كاملة لكل نقطة أدناه، بينما قسم الفني لا يأتي على أي منها:

- **لا سجل تاريخي لفحوصات الفني**: الداشبورد يستبعد المكتملة عمدًا (`dashboard/page.tsx:30`)، ولا توجد أي شاشة "فحوصاتي السابقة". الفني لا يقدر يشوف ما أنجزه هو تحديدًا. (الإدارة لديها `/dashboard/tests` مع بحث/فلاتر/تفاصيل.)
- **لا قائمة عينات خاصة به**: الفني يصل للعينة فقط عبر المسح (`scanner` ص45)؛ لا قائمة عينات أخذها/حضّرها، بينما الإداري يملك `/dashboard/samples` كاملًا.
- **لا صندوق تنبيهات للفني**: `NotificationBell` يوجّه إلى `/dashboard/notifications` (مسار إداري فقط) (`NotificationBell.tsx:65`)، ولا يوجد مسار تنبيهات تحت `/technician`. بل الإشعارات التي تُنشأ عن أفعال الفني تُوجه للمديرين فقط (`tests/[id]/page.tsx:227-247`, `attendance/page.tsx:68-74`) — الفني لا يصله إشعار عندما تُسند له مهمة.
- **لا تقرير عن مشكلة/عطل**: مرجعية المعدات موجودة للإدارة (`/dashboard/equipment`) لكن لا توجد أي صفحة بلاغ عطل أو مشكلة عينة من الفني.
- **لا جدول مهام منظم**: "مهامي" قائمة مسطحة بحد أقصى 50 (`dashboard/page.tsx:32`) — لا ترتيب أسبوعي/يومي، لا تقويم (الإدارة تستخدم `react-big-calendar` في الحجوزات).
- **لا طلبات إجازة/إضافي**: وحدات `/dashboard/hr/leaves` و`/dashboard/hr/overtime` غير متاحة للفني.
- **لا حضور ذاتي بسجل**: صفحة الحضور تعرض اليوم فقط وتكتب بدون `geo` أو حساب تأخير، بينما الإدارة تعرض سجلًا كاملًا بحساب ساعات (`computeWorkHours`).
- **ملف شخصي بلا تحرير ذاتي**: `profile` للقراءة فقط — لا يستطيع الفني تحديث هاتفه مثلًا.

## 5. الأمان والصلاحيات الخاصة بهذا القسم

- **الأساس سليم**: `proxy.ts` يمنع الوصول لـ `/technician/*` (وأحيانًا حتى غير موقّع/دور خاطئ) عبر جلب دور الموظف من Appwrite (`proxy.ts:29-51, 95-97`)، ويفحص الدور أيضًا عميلًا في `AuthGuard` لكن صفحات الفني لا تستخدم `AuthGuard` نفسها (تعتمد على proxy وعلى فحص `user` اليدوي في `dashboard/page.tsx:24` فقط).
- **IDOR — فحص بدون تحقق من الملكية**:
  1. `tests/[id]/page.tsx`: `getTest(testId)` ص72 و`updateTest(testId, payload)` ص213 **بلا أي تحقق أن `test.assignedTo === employee.$id`**. أي فني يستطيع فتح/تعديل/إكمال أي فحص مهما كان مسنده، بتغيير المعرّف في الرابط فقط. هذا أكبر ملاحظة أمنية.
  2. `vehicles/[tripId]/edit`: `getVehicleTrip(tripId)` ص39 و`updateVehicleTrip` ص70 بلا تحقق أن `driverId` له — يمكن للفني إنهاء/تعديل رحلة زميل.
  3. `samples/[id]`: قراءة أي عينة بلا ملكية (مخاطرة قراءة معلومات فقط).
- **/api غير محمي بالدور**: matcher في `proxy.ts:102-107` يغطي `/dashboard` و`/technician` فقط، بينما `/api/dashboard-stats` يتحقق من وجود كعكة جلسة فقط **دون فحص الدور** (`src/app/api/dashboard-stats/route.ts:6-15`)، ويعيد بيانات مالية/تشغيلية (فواتير `paidAmount`, حجوزات, أسماء موظفين) (`dashboard-stats.ts:129-189`). أي مستخدم موقّع (فني) يستدعي الـ endpoint مباشرة، وتصنيف الأخطر يعتمد على أذونات المجموعات في Appwrite (لو مسموح «أي مستخدم موقّع» = قراءة فنية تامة للمالية).
- **حماية «غير مسجّل» زائدة/ميتة**: واجهة "الوصول إلى العينة" بخيارَي دخول في `samples/[id]/page.tsx:98-124` لن تُعرض أبدًا لأن `proxy` يعيد توجيه غير الموقّع إلى `/technician/login` قبل الوصول للصفحة — كود ميت (ليس ثغرة لكنه تضليل).
- QR يشير لمسار Admin (`samples/[id]/page.tsx:129`) — يعيد فني إلى `/unauthorized` خارج تطبيق الماسح.

## 6. الأداء

- **كل صفحات الفني مكوّنات عميلية مع Appwrite SDK كاملًا** في الحزمة المرسلة — لا Server Components/Server Actions لجلب البيانات رغم أن القسم استهلاكي/عرضي بدرجة كبيرة (`dashboard`, `profile`, `samples/[id]`). على جوال ببيانات جوالية ضعيفة هذا يضيف حجم JS ويجعل كل جلب رحلة شبكة إضافية.
- **Over-fetching مؤكد**:
  - عند حفظ نتيجة فحص يُجلب كل الموظفين (limit 200) فقط للعثور على "مدير/إداري" (`tests/[id]/page.tsx:227-230`) — كل عملية حفظ تُنشئ جلبًا ثقيلًا غير ضروري.
  - صفحة العينة تنفذ حتى **6 استدعاءات متتالية** (`getSample`→`getProject`→`getClient`→`getEmployee`×3) بدون `Promise.all` (`samples/[id]/page.tsx:34-57`) — زمن استجابة تراكمي.
  - `vehicles/page.tsx:31-56`: جلب رحلات 50 + مركبات 50 بدون فهارس خدمية.
- الماسح يحمّل `html5-qrcode` ثقيلة (~200KB) لكنه معزول بروتيًا (code-splitting) — جيد.
- خطوط Google (IBM Plex Arabic) تُحمّل من شبكة عند كل تثبيت بدون استراتيجية cache.
- `providers` يحجب كل الشاشات بـ "جارٍ التحقق من الجلسة" حتى يكتمل `checkSession` (`Providers.tsx:15-22`).

## 7. الاقتراحات المرتبة حسب الأولوية

### أولوية عالية (تعيق العمل أو مخاطر أمنية)
1. **تحقق ملكية في `tests/[id]`** — منع IDOR: التأكد أن `test.assignedTo` يساوي الفني قبل العرض/الحفظ (`tests/[id]/page.tsx:72,213`) وإلا لقطة/رسالة رفض.
2. **فصل مسار إدخال 7 أيام عن 28 يومًا** — السماح بحفظ مؤقت بحالة "تحت الفحص" وعدم إخفاء الفحوصات بفترات مكتملة ناقصة من الداشبورد (`dashboard/page.tsx:30, tests/[id]/page.tsx:156`) وإلا تُفقد نتائج 28 يوم.
3. **حماية `/api/dashboard-stats` بالدور** — عنده جلسة فني تُستدعى بيانات مالية (`route.ts:6-15`)؛ إضافة فحص `role` خادمًا أو إدراج `/api/*` في مراقبة proxy.
4. **معالجة فشل الشبكة بصراحة في الداشبورد والكتابة** — `dashboard/page.tsx:28-46` بلا catch يعرض "لا توجد مهام" مضللًا؛ ويجب منع تكرار يوم الحضور عند فشل جلب السجل (`attendance/page.tsx:43`).
5. **توجيه QR داخلي صحيح** — التناسق بين `/dashboard/samples/{id}` (المولّد) ومسار `/technician/samples/{id}` (`samples/[id]/page.tsx:129`) حتى يصل الفني بعد مسح خارجي.

### أولوية متوسطة (أثر واضح لكن غير حرج)
6. **سجل فحوصات الفني و"مهامي" منظم بالأيام/الأسبوع** — بدل قائمة مسطحة 50 (`dashboard/page.tsx:30-46`)؛ الاكتمال اللاحق أولًا.
7. **تنبيهات داخل قسم الفني** — NotificationBell مقطوع عن `/technician` (`NotificationBell.tsx:65`)؛ الفني لا يعرف بإسناد مهمة جديدة.

9. **أهداف لمس أكبر للعناصر الصغيرة** — أزرار حذف مكعب 16px و"إضافة مكعب" وزر خروج الداشبورد (`TestResultRowsEditor.tsx:71`, `dashboard/page.tsx:63`).

### أولوية منخفضة / لاحقًا (تحسينات لطيفة)
11. **إضاءة/تبديل كاميرا للماسح** — دعم torch و`facingMode` أمامي لتوضيح الإضاءة (`scanner/page.tsx:31`).
12. **تحسين جلب العينة** — `Promise.all` للاستدعاءات الست المتتالية (`samples/[id]/page.tsx:34-57`).
13. **تقليل حجم الحزمة للجوال** — نقل الجلب إلى Server Components/Server Actions في صفحات القراءة (dashboard/profile/samples) وحصر Appwrite SDK côté serveur؛ وإضافة ذاكرة مؤقتة لـ `listEmployees` في حفظ النتيجة (`tests/[id]/page.tsx:227-230`).
14. **إكمال PWA واقعية** — `manifest.json:8` بـ `icons: []` وبلا Service Worker؛ تعبئة الأيقونات ولو تجربة offline موجّهة للحضور والرحلات.
15. **سجل حضور/رصيد ذاتي للفني** — عرض سجله الشهري مع ساعات العمل (يوجد `computeWorkHours` في الإدارة) قبل طلب الإجازة.
